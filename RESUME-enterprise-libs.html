Ringkasan Proyek

enterprise-libs adalah monorepo framework enterprise yang menyediakan modul-modul siap pakai untuk backend berbasis Quarkus/Java dan frontend berbasis Nuxt 3/TypeScript. Framework ini dirancang untuk mempercepat pengembangan aplikasi enterprise dengan mengikuti arsitektur microservice, containerization Docker, enkripsi data tingkat enterprise, sistem tema dinamis, dan dukungan multi-database (PostgreSQL, MariaDB, MSSQL) tanpa perubahan kode — cukup ganti environment variable. Frontend tidak perlu diubah karena hanya bicara ke REST API.

Modul Backend (3 Modul)

quarkus-db-adapter
Abstraksi database enterprise — PostgreSQL, MariaDB, MSSQL
  • BaseEntity — id SEQUENCE/50, createdAt, updatedAt, createdBy, updatedBy
  • PageResult<T> — generic paginasi: data, total, page, size, totalPages
  • BaseRepository<E> — findAllPaginated, findByQueryPaginated, saveOrUpdate
  • DatabaseHealthCheck — @Liveness @Readiness via JDBC isValid(2)
  • Driver: quarkus-jdbc-postgresql + mariadb + mssql
  • Config: DB_KIND + DB_URL (full JDBC URL per vendor)
quarkus-encryption
Library enkripsi enterprise multi-algoritma
  • AES-256-GCM — 12-byte random IV, output Base64(IV+ciphertext)
  • RSA-2048 OAEP — generateKeyPair, load dari Base64
  • BCrypt password hash (cost=12) + SHA-256/512 checksum
  • HMAC-SHA256 + safeEquals() constant-time comparison
  • REST endpoint opsional (toggle via application.properties)
quarkus-theme-api
REST API manajemen tema dinamis — support PostgreSQL, MariaDB, MSSQL
  • Theme model — PanacheEntityBase + @GeneratedValue(IDENTITY) untuk semua DB
  • ThemeService — CRUD + activate() deactivate-all-others logic
  • 7 REST endpoint: GET /themes, /active, /{id}, POST, PUT, /activate, DELETE
  • Flyway locations dinamis: db/migration/${DB_KIND}
  • Migration terpisah: postgresql/ · mariadb/ · mssql/
  • Docker compose: DB_URL pakai hostname service Docker (bukan localhost)

Fitur Enterprise yang Diimplementasikan

✓Microservice Architecture

Setiap modul independen dengan pom.xml/package.json sendiri, bisa di-deploy terpisah via Docker. Tidak ada coupling antar modul.

✓Container Friendly

Multi-stage Dockerfile di setiap modul. docker-compose.yml dengan healthcheck, environment variables, dan volume management.

✓Binary Apps Conversion

GraalVM native profile (-Pnative) tersedia di tiap modul backend. Kompilasi ke native binary tanpa JVM — startup <50ms, memory <50MB.

✓Database Adapter — Multi-DB

Support PostgreSQL, MariaDB, dan MSSQL. Cukup set DB_KIND + DB_URL. Flyway otomatis pilih migration SQL yang sesuai vendor.

✓Encryption Adapter

AES-256-GCM (data at rest), RSA-2048 OAEP (key exchange), BCrypt (password), HMAC-SHA256 (integrity), constant-time compare.

✓Themes Adapter

Design tokens (JSON) disimpan di DB → quarkus-theme-api → diambil nuxt-theme-lib → diterapkan sebagai CSS variables ke seluruh UI.

Quick Start

# Clone & setup
git clone https://github.com/JackD-Creator/Java-Devx.git
cd Java-Devx/enterprise-libs

# Jalankan dengan PostgreSQL (default)
cd backend-libs/quarkus-theme-api && docker compose up -d

# Ganti ke MariaDB — edit .env lalu docker compose up
DB_KIND=mariadb  DB_URL=jdbc:mariadb://mariadb:3306/themedb

# Ganti ke MSSQL
DB_KIND=mssql  DB_URL=jdbc:sqlserver://mssql:1433;databaseName=themedb;encrypt=false

# Test API — semua endpoint verified live
curl http://localhost:8080/api/themes          # list all
curl http://localhost:8080/api/themes/active   # get active
curl http://localhost:8080/q/swagger-ui        # Swagger UI

Technical Issues Resolved

Bug #1 — Hibernate Sequence Not Found
PSQLException: relation "themes_seq" does not exist
@GeneratedValue(strategy = IDENTITY) → pakai BIGSERIAL native
Root cause: PanacheEntity default pakai SEQUENCE strategy dan mencari themes_seq, padahal PostgreSQL BIGSERIAL membuat sequence berbeda nama.
Fix: Ganti ke PanacheEntityBase + @GeneratedValue(IDENTITY) — kompatibel PostgreSQL (BIGSERIAL), MariaDB (AUTO_INCREMENT), dan MSSQL (IDENTITY) sekaligus.
Bug #2 — Docker DB Connection Refused
DB_HOST=postgres → app default ke localhost:5432
DB_URL=jdbc:postgresql://postgres:5432/themedb
Root cause: docker-compose.yml set env DB_HOST tapi aplikasi membaca DB_URL. Container tidak bisa resolve localhost ke service Postgres di jaringan Docker.
Fix: Set DB_URL lengkap dengan hostname service Docker (postgres), bukan localhost.
